# 03 — Consumer view

This server has no player UI. Its consumers are the Unity client (WebSocket + 2 HTTP routes),
`game-backend` (receives calls), and an admin (dashboard).

## Unity client → MP (unchanged except the token)

**Rooms:** `ludo_friends`, `ludo_test_room`.

**Join options (unchanged):** `clientKey`, `matchMode`, `roomCode`, `playerIds`,
`playerStartIndexes`, `safePointIndexes`, `commonTrackCount`, `commonPathCount`, `pawnCount`,
`expectedPlayerCount`, `totalMoveCount`, `playerProfile`.
**New:** the access token, sent through Colyseus' auth mechanism (not as a join option).

**Client → server messages (unchanged):** `dice_roll_request`, `pawn_move_request`,
`sync_state_request`, `chat_request`.

**Server → client messages (unchanged):** `room_joined`, `room_state`, `game_started`,
`turn_started`, `turn_ended`, `dice_rolled`, `pawn_move_available`, `pawn_moved`, `pawn_death`,
`bot_status_changed`, `chat_message`, `game_over`, `error`.

**HTTP (used by the client's room list, stay public):** `POST /rooms/exists`,
`POST /rooms/player-active`.

## MP → game-backend

| Call | Auth | Purpose |
|---|---|---|
| `GET /internal/users/:userId/profile` | `Bearer MULTIPLAYER_API_KEY` | display profile |
| `POST /internal/matches/room-result` | `Bearer MULTIPLAYER_API_KEY` | finished match |

Contract owned by `game-backend` docs; the shapes here are proposals.
